Filled the SP-build gaps so these classes spend SP instead of banking it forever:
- **Pirate tree** → new `server.bots.build.PirateBuilds` (Pirate/Brawler/Marauder/Buccaneer knuckle path + Gunslinger/Outlaw/Corsair gun path), wired into `BotBuildManager.getBuildOrder` + `getSupportedBuildPath`.
- **Paladin** → `WarriorBuilds.paladinBuild` (trains SWORD_HOLY_CHARGE to stay sword, matching the sword White Knight build).
- **F/P mage line** (FP_WIZARD/FP_MAGE/FP_ARCHMAGE) → `MageBuilds`.
- Also added the missing `getSupportedBuildPath` rows for DARKKNIGHT + the IL mage line (builds existed; only respec couldn't reach them — pre-existing oversight).

Build orders adapted from pre-Big-Bang (v83-accurate) DigitalTQ guides, cross-checked vs the MapleRoyals forum guides (Donn1e buccaneer, Nemo corsair, Haplopelma paladin, GoodDoodoo F/P) — URLs cited in each build file.

Pirate has the SAME weapon-gate/variant problem as thief (see [[kb_bot_thief_claw_dagger_split]]): `BotEquipManager.isWeaponCompatible` (BotEquipManager.java ~2230) keys the pirate weapon line off the trained 1st-job attack — Double Shot → gun-only, Flash Fist/Somersault Kick → knuckle-only. So the Pirate 1st-job build must commit knuckle/gun before any SP lands. Solved by REUSING the shared `entry.spVariant` field with values "knuckle"/"gun" via `resolvePirateVariantIfNeeded` (mirror of `resolveThiefVariantIfNeeded`), plus a `plannedOrPicked` weapon-safety guard (Double Shot→Gunslinger, Flash Fist/Somersault→Brawler). No collision with thief's "claw"/"dagger" since a bot is never both.

**Pirate AP build: DONE** (commit after the SP-build commit). `apPromptForJob`/`apBuildOptions` now return a pirate case: gun line (Gunslinger/Outlaw/Corsair) is DEX-primary → STR-secondary ("strless"/"25 str"); knuckle line + base Pirate is STR-primary → DEX-secondary ("dexless"/"25 dex"). `resolveApBuild` orients base Pirate (job 500, which `BotScrollManager.mainSecondary` defaults to `{s,d}`) by reading the UPGRADED 1st-job attack skill via `BotBuildManager.pirateIsGun(bot, entry)` — the shared SSOT that mirrors the weapon gate: Double Shot trained → gun `{d,s}`, Flash Fist/Somersault → knuckle, with `entry.spVariant` only as the pre-SP-spent fallback (robust to stale/unset variant on relog/mid-career spawn). (2nd+ pirate jobs 51x/52x are already correct in mainSecondary.) Owner-reply parse in `BotChatManager.handleApBuildSelection` via `isKnucklePirate`/`isGunPirate`, which delegate to `pirateIsGun` (no duplicated logic). `pickWeightedJob` now includes pirate (all 5 explorer 1st jobs buildable; JOB_WEIGHTS already had PIRATE=1). Tests added in BotBuildManagerTest (gun/knuckle SP routing, gun resolveApBuild, pickWeightedJob-includes-pirate).

**1st-job weapon-line picker (owner-facing), commit 678ed3649:** supervised thief/pirate now ask the owner to pick the weapon line at 1ST JOB ("claw or dagger?", "knuckle or gun?") via `buildSpVariantPrompt` (extended beyond Hero; `spVariantOptions(Job)` job-aware), mirroring Hero's 1h/2h picker. The pick is AUTHORITATIVE: `autoAssignSp` HOLDS 1st-job SP for a supervised base thief/pirate until answered (variant resolvers now roll ONLY for ownerless bots — `if (!isOwnerless) return` before the roll); `commitWeaponLineVariant` stores variant + persists matching planned 2nd job + spends held SP; reply parsed in BotChatManager (SP_CLAW/DAGGER/KNUCKLE/GUN_PATTERN). At lv30 a committed thief/pirate AUTO-ADVANCES to the determined 2nd job (claw→Assassin, dagger→Bandit, knuckle→Brawler, gun→Gunslinger) via `committedSecondJob` — no "assassin or bandit?" re-prompt; falls back to the choice prompt only if never committed (self-heals). NOTE: `thiefBuildFollowsRequestedFirstJobOrder` was 50/50-flaky (relied on the roll) — now commits claw explicitly.

KNOWN minor gap (bounded, not fixed): owned base-Pirate AP *prompt text* is always knuckle-oriented ("dex") since `apPromptForJob(Job)` can't see the variant; a gun-bound base pirate's prompt says "dex" but the parse + autonomous path are variant-correct. Self-corrects at 2nd job. Also `BotScrollManager.mainSecondary` base-Pirate (500) equip-scoring still defaults STR (variant not threaded in) — tiny lv10-30 window, left alone.

**Damage formula: VERIFIED CORRECT for pirate.** SSOT is `Character.calculateMaxBaseDamage(watk, weapon)` (Character.java ~851): GUN → `(3.6·DEX + STR)·watk/100` (DEX primary), KNUCKLE → `(4.8·STR + DEX)·watk/100` (STR primary); multipliers in `WeaponType` (GUN 3.6, KNUCKLE 4.8). Masteries wired in `CombatFormulaProvider` (~954): KNUCKLE→Brawler.KNUCKLER_MASTERY, GUN→Gunslinger.GUN_MASTERY. Normal pirate attacks pass `damageWeaponType=null` (damageWeaponTypeForAction only overrides spear/polearm/general), so they use the weapon-aware SSOT — NOT the hardcoded-STR `physicalMaxBaseDamage` helper (that's only for DK spear/polearm forced skills). Routing: knuckle→CLOSE, gun→RANGED. Degenerate gun-bash/claw-punch handled separately (resolveDegenerateDamageProfile). NON-formula behavioral gaps (future): bot doesn't gate Marauder/Buccaneer Energy-Blast on a full Energy Charge bar, nor Corsair Battleship-Cannon on being mounted (Rapid Fire works off-ship, so corsair still functions).
