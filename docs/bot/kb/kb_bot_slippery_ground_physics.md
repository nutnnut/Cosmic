Slippery ground (map WZ `info/fs` < 1, El Nath 0.2) in BotPhysicsEngine — commits fb5ea4317 + 91cd9462f:

- **Kinetic regime, NOT the force/drag model**: while a direction is held, constant accel `SLIP_WALK_ACCEL_PXSS(1400)·fs` px/s² with hard cap at the profile walk speed (cap scales with speed stat, accel does NOT); on release, constant glide decel `SLIP_GLIDE_DECEL_PXSS(400)·fs` px/s² (client halves friction when fs<1: 800/2). Linear ramps, fitted to `logs/monitored-packets-elnath-slippery-walk-left-right-spd{100,110}.log` (residuals ≤3.1 px/s, both stats, fit script `tmp/snowfit/fit.py`). The fs=1 path is bit-identical to the old model — only `applySlipperyGroundStep` branches.
- **Packet parsing**: inbound 0x29 = 1 byte + 4-byte CRC + start x,y int16, then movement list; type-0 element = type,x,y,vx,vy,fh,stance,dur — **(x,vx) is the state at the END of the element's duration**, vx in px/s. Stances 2/3 walk R/L, 4/5 stand R/L (stand elements with decaying vx = the slide).
- **launchRunwayPx on fs<1**: `step*6 + vmax²/(2·1400·fs)` (~28 px extra at El Nath), replacing the `step*6/fs` 180px over-reserve.
- **Snowshoes**: worn-shoe WZ `info/fs ≥ 1` (ids 1072168-71, 1072238/39, 1072338, 1072510, 1072819; all use 10) cancel slip. `BotMovementProfile.snowShoes` (slot -7 lookup via getEquipStats — `fs` key added to it in ItemInformationProvider). Graph cache keys on the flag; `canonicalProfile` strips it on non-slippery maps so normal graphs aren't doubled; `peekClosestGraph` adds 1000 distance for flag mismatch.
- **Counter-strafe braking**: `counterStrafeBrakeDir` — when movement wants moveDir=0 but the bot still slides on slippery ground, hold the opposite direction (1400·fs brake vs 400·fs glide = 3.5×, 28 px vs 98 px stop). Hooked in `applyGroundMotion`; graphgen validates slippery jump landings as brake-to-stop (`POST_LANDING_BRAKE_TICK_CAP=240`) instead of the held-direction window → small platforms landable on ice, no extra graph state.
- **Stop policy refined (a6e5ab219)**: `slipperyStopDir` — GLIDE like a player (packet-true 80·fs) unless the projected glide-out slides off a ledge, then counter-strafe brake, releasing when safe. Shared by runtime tick and graphgen landing sim.
- **Air physics (packet-fitted, `logs/monitored-packets-elnath-tricky-jumps-spd100v2.log`, commits 970348c90+eb7418d14)**: (a) LAUNCH SNAP — direction held at takeoff snaps vx to ±walkSpeed instantly (so directional jumps at ±walkStep were already client-true); NO-INPUT jumps carry the ground slide momentum; (b) air control = **200·fs px/s²** capped at walkSpeed, no drag — fs scales AIR control too (El Nath 40), and this REPLACED the old ad-hoc AIR_STEER 0.5/1.5 model on fs=1 maps as well (full mid-air reversal possible); (c) LANDING HALVES momentum exactly (125→62), and opposite input at touchdown ZEROES it (the real counter-strafe-landing effect). Caveat: same-direction sub-cap air accel assumed symmetric with measured counter-strafe (noted in docs/bot/physics-client-audit.md §6).
- **El Nath benchmark tests** (BotNavigationGraphProviderTest): trick chain fh 171>262>264>267>277>278>279 + fh 258-from-below, user-verified in client at speed100/jump100 no snowshoes. Half-momentum landings are what unlocked the chain (+51 jump edges, build time unchanged).
- **Air model corrected per disasm (5c4cbb8fd)**: CVecCtrl::CalcFloat truth — the 200·fs air force only applies while velocity-in-input-direction < vmax_air = **8.93·fs px/s** (hard clamp at band edge, NO-OP beyond → no forward accel mid-air); no-input drag 1·fs px/s², **100·fs at terminal fall**. Counter-strafe-through-zero unchanged. Executor holds the launch key during committed arcs (client no-op that suppresses drag → constant-vx arcs match graph sims). v55 graphs byte-identical to v54.
- **Approach control + brake stance (fa51f5e3d, evidence pathlog-Preston-2026-06-12T083326.txt)**: all ground walk-toward-target funnels through `BotMovementManager.updateStepX`; on slippery ground `BotPhysicsEngine.slipperyApproachDir(map, profile, hspeed, dx)` is bang-bang — accelerate only while next-tick stop-out (brake+residual glide, 8ms quanta) fits in |dx|, else brake — so bots stop inside 2px launch windows at platform edges instead of sliding off (the Preston fall). Walk-off DROP edges exempt (need momentum). Braking (`desiredDir·hspeed<0`) sets facingDir=input + `BotEntry.groundBrakeDir` → resolveStance renders the visible counter-strafe walk stance.
- GRAPH_VERSION: 50→51 (kinetic+snowshoes) →52 (brake-to-stop landings) →53 (glide-unless-edge stop policy) →54 (half-momentum landings + air control in jump arcs) →55 (CalcFloat band correction; v55 ≡ v54 content). hspeed units are px per 8ms client step; px/s = hspeed/0.008.
