Thief 1st-job build split + no-ammo recovery (experimental branch, 2026-06-20).

**Problem:** claw Rogues need throwing stars (ammo+meso); ran dry+broke = deadlock (claw skills fail combat ammo gate, no fallback). Also 2nd job was uniform-random Assassin/Bandit regardless of trained skill, and Bandit/ChiefBandit/Shadower had NO SP build (banked SP forever).

**Fix (slices 1+2; slice 3 deferred):**
- `build/ThiefBuilds.java`: `getBuildOrder(Job, variant)` now; variant `"claw"` (Lucky Seven path, existing) vs `"dagger"` (Double Stab path). Added `daggerRogueBuild` + `banditBuild`/`chiefBanditBuild`/`shadowerBuild`. Dagger trees from royals.ms Donn1e Shadower guide (link credited in file header). Two bot deviations vs guide: (a) dagger Rogue skips the guide's 1-pt Lucky Seven (any Lucky Seven flips the weapon gate to claw-only and would strand the dagger build); (b) ChiefBandit prioritizes Band of Thieves over Meso Explosion and dumps the leftover into Pickpocket (a bot can't meso-bomb); (c) Shadower maxes Boomerang Step before Assassinate (grind AoE > boss single-target).
- `BotBuildManager`: `resolveThiefVariantIfNeeded` sets `entry.spVariant` (reuses the Hero 1h/2h mechanism) — infers from trained skill / 2nd+ job, else fresh Rogue derives from planned 2nd job, else 50/50 roll and `tiePlannedSecondJob` FORCES+persists the matching planned 2nd job (claw→Assassin, dagger→Bandit) so build+advance+name align. `plannedOrPicked` has a thief safety guard (Double Stab→Bandit, Lucky Seven→Assassin). `getSupportedBuildPath` gained BANDIT/CHIEFBANDIT/SHADOWER (respec). Weapon gate `BotEquipManager.isWeaponCompatible` already keys off trained skill (Lucky Seven=claw / Double Stab=dagger) — it's the SSOT, no change needed.
- Slice 2 (out-of-ammo deadlock): `BotShopManager.isOutOfUsableAmmo` (ranged-ammo weapon + countAmmo<=0). Wired into the reactive errand (`BotPotionManager` ~L441, ungated by meso) and the pre-travel errand (`BotAutopilotManager` ~L494). At the shop, ammo is already bought BEFORE pots (reserve-by-ordering) and sell-trash is the tail of every visit — so a fully-broke bot recovers over two town trips. NOTE: the shop sequence buys-before-sells, so one-trip recovery when broke is NOT implemented (acceptable ceiling).
- Slice 3 (truly-broke guardrail) DONE 2026-06-20 (commit after f5775044c): the dagger-SWAP idea was the wrong escape (a claw Rogue owns no dagger; user confirmed it sold its spare weapon). Real fix = let the bot farm with the **degenerate close-range swing that already exists** for no-ammo ranged weapons (`shouldDegenerateForNoAmmo` -> CLOSE route claw punch / point-blank shot, no ammo, no client crash since the point-blank-bow infra already emits it). THREE things blocked it, all fixed: (1) `BotCombatManager.attackMonster` hard-returned on `entry.noAmmo` -> now `entry.noAmmo && route != CLOSE` (RANGED still blocked, the degenerate CLOSE swing fires); (2) the ranged-spacing retreat kept pushing the no-ammo bot AWAY from mobs so the swing never landed -> `noAmmoMelee = isOutOfUsableAmmo(bot)` suppresses `rangedSpacingCrowded` + the spacing clause of `shouldRetreatForRangedSpacing` in `BotManager.tickCore` (~L3440; danger-retreat still applies); (3) all THREE out-of-ammo resupply-errand triggers (BotPotionManager ~L441, BotAutopilotManager ~L497, BotCombatManager ~L2979/2988) fired unconditionally -> now gated on new `BotShopManager.canRecoverAmmo(entry,bot)` = `meso >= cfg.AMMO_BUY_FLOOR_MESO(1000)` OR `shouldAutoSellTrash` (has cramped sellable junk). When NOT recoverable the bot stops bouncing to town and degenerate-farms in place to earn meso, then resupplies normally once it crosses the floor. See [[project_bot_independence_infra]] [[kb_bot_ranged_spacing_weapons]].

**Tiered self-economy spend policy (2026-06-20, same branch):** 3 cfg knobs in `BotManager.cfg` — `AMMO_RESERVE_MESO=10k`, `POT_SPEND_MIN_MESO=20k`, `TAXI_MIN_MESO=50k`. Priority fight>survive>convenience.
- Pot gate: `canAffordPotResupply` now `>= POT_SPEND_MIN_MESO` (20k, was RESUPPLY_MIN_MESO 5k) — strict no-pot under 20k; survival leans on the EXISTING low-HP retreat (`shouldProactivelyRetreat`/`isFragile` already counts no-pots as fragile → retreats from touch-dangerous mobs) + passive regen.
- Taxi gate: `BotWorldGraph.expand()` drops paid Victoria-cab shortcut edges when `meso < TAXI_MIN_MESO` (gated inline off the existing RouteOptions.meso — NO new field/call-site churn); cross-continent rides (no walk alt) always allowed via `CONTINENT_RIDE_NPCS={22000 Shanks,2060009 Dolphin,1002002 Pason,2090005 Crane}`.
- Equip-buy budget now reserves `AMMO_RESERVE_MESO` (was RESUPPLY_MIN_MESO).
- **Buy-fresh-ammo bug fixed:** `findAmmoItem` was BOW/CROSSBOW only + `needsAmmo` bow-only, so a claw/gun bot that LOST its whole rechargeable set could never rebuy (doRecharge only refills an existing stack). Added CLAW→isThrowingStar/GUN→isBullet to findAmmoItem + `shouldBuyStarterAmmoSet`/`buyStarterAmmoSet` (buys 1 cheap set when bestRechargeAmmoId<0), wired into needsToBuySupplies + shopHasAnythingNeeded + executePurchases (buys set BEFORE recharge so it tops up same visit).
