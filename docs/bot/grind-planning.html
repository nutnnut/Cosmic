Bot Grind Planning

How a bot (or a party) decides where to grind: the exact formulas behind gear drops, scroll drops, exp, mob difficulty, multi-mob maps and travel cost.

Code: BotGrindAdvisor (builds candidates from world data), BotGrindPlanner (pure scoring/selection), BotTravelCost (travel penalty), BotScrollManager (offense score SSOT). Wiring: BotAutopilotManager.

1. The candidate: one map, its mobs blended by spawn share

A candidate is a map, not a single mob. The bot kills whatever it encounters, so time spent on one mob is time not spent on another. Every per-mob number is weighted by that mob's share of the map's spawn points:

sharei = spawnPointsi / Σ spawnPoints   (over the map's grindable mobs)

killSeconds(map) = Σ sharei · killSecondsi
exp(map) = Σ sharei · expi · expRate
chancePerKill(item) = Σmobs i dropping it sharei · dropChancei · dropRate / 1,000,000

So a map mixing a great-exp mob with a poor one scores in between, weighted by how much of each you actually meet, and an item's effective rate is diluted when its dropper shares the map with junk mobs. Mobs the bot can't grind (bosses, friendlies, anything it can't meaningfully damage, 0-exp props) are excluded from the blend entirely — they don't dilute, because the bot won't engage them, but they also don't add density (see seek time below). The candidate is labeled with the dominant mob (most spawn points; exp breaks ties) for chat.

Skipped maps: towns, instanced/event fields (mapId ≥ 900000000), maps with fewer than 3 grindable spawn points.

2. Mob difficulty: inferred through kill time, not a separate check

There is no "difficulty rating". Difficulty enters the model exactly once, as time to kill one mob for THIS bot, computed from the same combat model the bot fights with:

perAttack = estimateBestSkillHitDamage(bot, mob)  // skill damage SSOT; falls back to expectedDamageAfterDef(maxBaseDamage(totalWatk), mob WDEF)
dps = perAttack / 0.72s  // attack cycle anchor
killSeconds = max(0.72, mobHP / dps)

A tanky or high-WDEF mob takes longer to kill, which lowers kills/hour, which lowers both its exp/h and its drops/h — so "hard but rewarding" vs "easy but mediocre" is a fair fight in the same units. If perAttack ≤ 0 the mob is unkillable for this bot and drops out of the map blend.

Seek overhead (walking between spawns) scales inversely with the map's grindable density:

seekSeconds = clamp(3.0 · 8 / spawnPoints, 0.5, 15)
killsPerHour = 3600 / (killSeconds + seekSeconds)
Not modeled (yet): death risk. A mob that out-damages the bot still looks attractive if it's technically killable. Touch damage, accuracy floors and potion burn are outside the model; in practice the level gap rarely lets that matter because unkillable = excluded.

3. What a drop is worth: the offense score SSOT

Every item value flows through one job-weighted offense score (BotScrollManager.offenseValue):

score = 5.0 · att + 1.0 · mainStat + 0.3 · secondaryStat
att = WATK (MATK for mages — MATK is worth 0 to everyone else)

One point of attack is worth five points of main stat; the wrong class's stats are worth nothing. This single scale is what lets gear, scrolls and exp compete.

3a. Equip drops — expected improvement over the worn roll

Drop stats are randomized (vanilla spread plus the rare "godly" uplift), so a drop's value is the expected improvement over what's already worn, Monte-Carlo'd through the real drop path (the same randomizeStats call the map uses), 32 samples:

scoreGain = E[ max(0, score(rolled drop) − score(worn)) ]
  • Empty slot → worth the full mean of the roll distribution.
  • Below-average worn roll → re-farming the same item stays moderately valuable.
  • Near-godly worn roll → almost every reroll is worthless → value decays to ~0.

This is the emergent stay-or-leave condition: no drop counters, no timers — the spot's value falls as the bot's roll improves, until somewhere else (travel-discounted) beats it. Gains below 0.5 score are dropped as rounding noise.

Both sides of the comparison also count scroll headroom — remaining upgrade slots are future stats:

potentialValue(equip) = score(equip) + 0.5 · remainingSlots · bestScrollEvPerSlot(type)
bestScrollEvPerSlot(type) = max over catalog scrolls applicable to the type of (effectiveSuccess · score(scroll stats))

The per-slot value is priced from the real scroll catalog through the self-scrolling rules (applicability, effective success, boom/meta scrolls excluded), so it is equip-type based, never flat: glove slots are worth att scrolls (~6.0 each at 60% +2 ATT), while pieces that only take stat scrolls get ~1.2 per slot. A fresh drop ships with full slots, so a weaker glove that still scrolls can out-value a stronger but maxed-out worn one — while the 0.5 discount (scrolls must still be obtained and survive their rolls) keeps bots from re-farming weak-scrolling pieces every few levels for slot count alone.

3b. Scroll drops — success-weighted stat value

Equip scrolls (item 2040000–2049999) are gear progression too. One scroll is worth its plain expectation:

scoreGain = effectiveSuccess · score(scroll stats)  // success incl. server bonus, capped 100%

No tiering anywhere — the "good scrolls" fall out by arithmetic: a 60% +2 ATT glove scroll is worth 0.6·10 = 6.0, beating a safe 100% +1 ATT (5.0) and a 10% +5 ATT long shot (2.5). ATT scrolls dominate stat scrolls 5:1 per point, and a MATK scroll is worth 0 to a non-mage. Gates: the bot must wear something the scroll applies to with an open upgrade slot, and boom-risk (cursed) plus meta scrolls (clean slate / modifier / white) are worth 0 — self-scrolling v1 refuses to use those, so farming them buys nothing.

Valuation only: actually applying scrolls stays behind the owner-confirmed self-scroll command. Sell-trash never sells scrolls.

4. Desirability and the two lenses

A jackpot the bot will never see shouldn't move the plan. Each prospect's appeal is its DPS fraction discounted by attainability within a 2-hour horizon:

dpsGainFraction = scoreGain / totalWornOffense
expectedCopies = chancePerKill · killsPerHour · 2h
desirability = dpsGainFraction · min(1, expectedCopies)

Each candidate map then gets two travel-weighted lenses:

expLens = exp(map) · killsPerHour · travelWeight(map)
gearLens = ( Σprospects desirability · killsPerHour · chancePerKill ) · travelWeight(map)

5. Travel penalty

Far maps are discounted by estimated travel time over the legal travel graph (Dijkstra over portal/scroll/taxi/ferry edges from the bot's current map):

travelWeight = max(0.25, 1 − travelSeconds / 3600)
portal hop 25s · return scroll 5s · taxi 30s · ferry = wait + ride from the live travel-rate config (rate 5 → 15min ride becomes 3min)

The current map costs 0s — home-field advantage. Staying wins while marginal reroll value holds; leaving wins when a discounted alternative overtakes it. Cross-continent (ferry) maps are only in the pool when sailing is allowed (owner offline/absent, or owner approved "sail away"; a ≥1.5× overseas advantage triggers a one-time ask).

6. Picking the spot: gear first, exp breaks ties

  1. If any candidate has desirability ≥ 0.02 (an attainable ~2% DPS gain), planning is gear-first: shortlist candidates within 70% of the best gearLens, then pick among the shortlist by expLens (weighted draw among those within 85% of the best, so a hundred bots don't pile onto one map).
  2. Otherwise: pure exp ranking (same near-best weighted draw).

So gear progression dominates whenever something attainable exists — and because godly rolls are rare, something nearby almost always qualifies — while exp quietly picks the best of the gear-comparable spots. With nothing worth farming, the bot reverts to a pure exp grinder.

7. Party planning: the whole party's gain, one map

The party picks one map by summing what every member gets out of it:

spawnPoints → spawnPoints / partySize  // members compete for spawns
memberScore(map) = gearLenŝ + 0.25 · expLenŝ  // each lens normalized to that member's best; pure exp if the member has no attainable gear
partyScore(map) = Σmembers max over the member's mobs on that map
pick = weighted draw among maps within 85% of the best partyScore

Because it's a sum of per-member bests, a map that feeds three members modest upgrades (or two upgrades and good exp for the rest) beats a map that's optimal for a single member — scaled by each member's own drop odds, kill speed and travel distance. Scroll and equip prospects are priced per member against their own worn gear, so the same drop can count for several members at once. Members with nothing useful on the picked map tag along as backup.

8. Farm-item mode ("farm <item>")

When the objective is a specific item, scoring is purely expected items/hour with the same spawn-share dilution — junk mobs sharing the dropper's map take kill time without dropping:

itemsPerHour(map) = chancePerKill(item, blended) · killsPerHour(map) · travelWeight(map)

Summary of the competition. Everything is converted to one currency (offense score per hour, travel-discounted): equips via expected-improvement-over-worn, scrolls via success×stat-value, both diluted by spawn share and drop odds; mob toughness prices itself through kill time; exp never outranks an attainable upgrade but decides among gear-equivalent spots — and for a party, the map that enriches the most members wins.
